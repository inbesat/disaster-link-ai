# Model Card — Flood Risk Classifier (XGBoost)

**Project:** Disaster Response Intelligence Platform
**Model:** Gradient-boosted decision tree (`XGBoost` classifier)
**Task:** 4-class flood risk classification
**Served by:** FastAPI microservice (`ml_service/api.py`)

---

## 1. System Architecture

```
┌─────────────────────────┐      ┌──────────────────────┐      ┌──────────────────────────┐
│   Next.js (Frontend)    │      │  FastAPI (Python)    │      │     XGBoost model        │
│  lib/ml-client.ts       │ HTTP │  ml_service/api.py   │ joblib │  flood_xgboost_model.pkl │
│  /api/predict           │ ───► │  /predict            │ ────► │  predict_proba()         │
└─────────────────────────┘      └──────────────────────┘      └──────────────────────────┘
                                        │
                                        ▼
                             ┌──────────────────────┐
                             │   PostgreSQL          │
                             │  flood_predictions    │  (persisted via Prisma)
                             └──────────────────────┘
```

**Flow:**
1. The map's `onMoveEnd` / geolocate (or the **What-If Simulator** sliders) fires a request to the Next.js route `GET /api/predict?lat=&lng=&rainfall=&saturation=&elevation=`.
2. `lib/ml-client.ts` formats the 4-model-features payload and POSTs it to the FastAPI service (`http://127.0.0.1:8000/predict`).
3. FastAPI loads the trained `flood_xgboost_model.pkl` on startup, runs `predict_proba`, and returns the predicted class + confidence.
4. `lib/ml-client.ts` maps class `0-3` to the UI labels **Safe / Watch / Warning / Evacuate**, persists the row to `flood_predictions`, and returns it to the UI.
5. If the Python service is unreachable, the client **gracefully falls back** to a default `Safe` result so the app never crashes.

## 2. Features

| Feature | Type | Meaning |
|---------|------|---------|
| `cumulative_rainfall_72h` | float (mm) | Total rainfall over the last 72 hours |
| `river_level_trend` | float (m) | Rate of river level change over 72h |
| `soil_saturation_index` | float (0–1) | How saturated the soil is (1 = fully saturated) |
| `elevation_m` | float (m) | Terrain elevation — low-lying areas are far riskier |

## 3. Target Classes

| Class | Label (UI) | Meaning |
|-------|------------|---------|
| 0 | **Safe** | Low risk, no action required |
| 1 | **Watch** | Monitor closely, prepare |
| 2 | **Warning** | Evacuation preparation / movement to shelters |
| 3 | **Evacuate** | Immediate evacuation recommended |

The target is engineered to correlate with high 72h rainfall, rising river trends, high saturation, and low elevation — the same physics that drive real flooding.

## 4. Training

- **Dataset:** `historical_flood_data.csv` — 1,000 synthetically generated rows.
- **Features:** the 4 above; **target:** `risk_level` (0–3).
- **Split:** 80/20 stratified train/test.
- **Model:** `XGBClassifier` (300 estimators, depth 6, lr 0.1, early stopping).
- **Metrics (test set):** Accuracy ≈ **0.82**; F1 ≈ 0.80 (macro).
- **Export:** `flood_xgboost_model.pkl` via `joblib`.

## 5. Synthetic Data & Production Path

> ⚠️ **Hackathon scope:** this model was trained on **synthetic data** generated by
> `generate_data.py` so the pipeline can be demonstrated end-to-end without
> scraping or labelling. The physics embedded in the generator mirror real flood
> dynamics, but the model has **not** seen real river gauge data.

The pipeline is designed to swap in real data for production:

- **IMD Open Data** — real-time rainfall / weather station feeds (the `weather_data`
  ingestion pipeline already fetches live rainfall via OpenWeatherMap).
- **CWC (Central Water Commission)** — live river water-level and discharge for
  Indian rivers → replaces `river_level_trend` with measured gauge data.
- **Soil moisture / terrain (Bhuvan / ISRO, SRTM elevation)** — replaces the
  derived saturation index and adds true elevation for each gauge/village point.

**How to retrain on real data:**
1. Collect historical rows of the 4 features + observed flood outcome per station.
2. Regenerate the training script input (`train_model.py` already reads a plain CSV
   with the same columns).
3. Run `python train_model.py` → it exports a new `flood_xgboost_model.pkl`.
4. Restart the FastAPI service; no frontend changes are required.

## 6. Limitations

- Trained on synthetic data; real-world accuracy may differ until retrained on
  IMD/CWC observations.
- Point-prediction only (no spatial interpolation across catchments yet).
- Does not yet model river-embankment breaches or drainage topology.
