## 🔧 AI Chat fixes (important history — don't redo this)

Four stacked bugs were diagnosed and fixed in the AI chat:

1. `anthropic/claude-3.5-sonnet` was removed from OpenRouter → HTTP 404.
2. Primary OpenRouter account had zero credits, backup had ~1,500 tokens (not enough for a reply).
3. Chat route used only `openRouterModel` — Groq/Bluesminds fallbacks existed but were never wired into `/api/chat`.
4. AI SDK v7 stops after ONE model step by default (`stopWhen: isStepCount(1)`) — tools were called but the final answer was never generated.

**Fix:** `lib/ai/openrouter.ts` was rewritten as a probe-based provider resolver: health-checks Groq → OpenRouter primary → OpenRouter backup → Bluesminds with realistic probe requests, skips unconfigured keys, caches the winner for 60s, dedupes in-flight probes, uses current model IDs. Added `lib/ai/openrouter.test.ts` (10 tests). Chat now runs on Groq's free tier — works great, zero cost. The resolver auto-switches to Claude if the OpenRouter account ever gets credits.

## ⚠️ Hard-won gotchas (don't repeat these)

1. Tailwind opacity modifiers on custom colors require `rgb(var(--x-rgb) / <alpha-value>)` in the config — plain `var()` colors silently drop `/40` etc.
2. `bg-primary` / `text-muted` / `border-subtle` / `bg-tertiary` are hand-written classes in globals.css, NOT theme colors — they can't take variants (`hover:bg-tertiary` won't work; use `hover:bg-[var(--bg-tertiary)]`).
3. Conflicting Tailwind utilities are resolved by stylesheet order, not class-list order — passing `className` overrides that conflict with a component's own variant classes silently loses. Don't tint override; add a prop instead.
4. Restart `npm run dev` after editing `tailwind.config.ts` — Next.js doesn't fully hot-reload it.
5. JSX comment syntax: `{/* */}` only, never plain `/* */` inside JSX props.
6. **Abspos elements are clipped by an ancestor's `overflow` when their containing block is inside that ancestor.** An `absolute left-full` tooltip inside an `overflow-x-hidden` scroll container is invisible — use a measured `position: fixed` tooltip instead.
7. **When a fade-out tooltip hides, keep position in a separate state from visibility** — resetting one shared state teleports the element to its `(0,0)` fallback and it fades in the corner.
8. Tailwind `first:`/`last:` variant utilities override the base utility for the first/last child (same specificity, later in the cascade) — standard pattern for dividers.
9. react-hot-toast's per-toast wrappers are absolutely positioned with inline styles — you cannot re-position the stack with CSS; flip the `position` prop via `matchMedia` instead. Hover-pause on the progress bar is visual only (the library's timer keeps running).
10. Prefer roadmap tokens over literal spec colors (`border-blue-500` → `border-accent-primary`) — same look, but re-themes in day-ops mode. Document any deviation in the summary.
