Next.js 14 - Server-First React Framework

Frontend
Beginner explanation: Next.js is like React's bigger brother. It knows where to run code - on the server for fast initial page loads or on the client for interactive buttons and forms. It uses a folder structure called the App Router where every folder equals a route.

Why We Use It

  • Server Components by default: Pages load faster because heavy code runs on the server and only the final HTML is sent to the browser. The user sees content instantly.
  • File-based routing: Creating a new page is as simple as creating a new folder and file. No need to configure routes manually.
  • Server Actions: You can write backend logic (like saving to a database) directly inside your form components without creating separate API routes.
  • Streaming and Suspense: Slow parts of a page show a loading spinner while fast parts render immediately. The user never stares at a blank screen.
  • Built-in optimization: Automatic image optimization, font loading, and script management out of the box.

Key Concepts

Server Components (default)

Run ONLY on the server. Can directly fetch data from databases and APIs. Their code is NOT sent to the browser, making pages incredibly fast. Cannot use useState or onClick - think of them as read-only data fetchers.

Client Components ("use client")

Run in the browser. Can use hooks like useState and useEffect, respond to clicks, and access browser APIs. You add "use client" at the top of the file to mark them. These are for anything interactive.

What is the App Router?

The App Router is Next.js 14's way of mapping URLs to pages. You create folders inside the "app" directory, and each folder becomes a URL path. A folder named "dashboard" becomes the "/dashboard" route. A "page.tsx" file inside that folder is what renders when someone visits that URL.

Layouts - Why They Matter

A layout is a shared wrapper (like a navbar and sidebar) that stays on screen even when the user navigates between pages. Only the content inside changes. This means faster navigation because the layout doesn't re-render every time.

Viva Points to Remember
  • "Why Next.js over plain React?" - Next.js adds server rendering, file-based routing, API routes, image optimization, and static generation. Plain React is client-only.
  • "What is SSR vs SSG vs ISR?" - SSR renders on every request (always fresh). SSG builds once at build time (fastest). ISR is static but re-generates periodically (best of both).
  • "What is the difference between Pages Router and App Router?" - App Router is the newer system in Next.js 13+ that supports React Server Components, layouts, and streaming. Pages Router is the legacy approach.

React 18 - The UI Library

Frontend
Beginner explanation: React is a JavaScript library for building user interfaces. Think of it as LEGO bricks - you build small components like buttons, cards, and forms, then compose them into full pages. React 18 added concurrent rendering (doing multiple things at once) and server components.

Core Concepts

Components

Reusable UI pieces. Functions that return JSX (HTML-like syntax). Each component manages its own piece of the UI. You nest components inside other components to build complex interfaces.

State (useState)

Data that changes over time. When state changes, React re-renders the component to show updated UI. Like a light switch - flip the state, and the screen updates automatically.

Props

Data passed from parent component to child component. Like function arguments. A child receives props and uses them to render. Props are read-only - children cannot change them.

What is New in React 18?

  • Concurrent Rendering: React can pause and resume rendering work. Urgent updates like typing in a search box are not blocked by slow updates like loading a large list.
  • Automatic Batching: Multiple state updates in the same event handler are grouped into ONE re-render instead of multiple, making the app faster.
  • Suspense: Lets you show a loading fallback while waiting for data. Enables streaming HTML from the server so the user sees content faster.
  • Server Components: Components that run only on the server. They can access databases directly and do not ship any JavaScript to the browser.
  • Server Actions: Functions marked with "use server" that run on the server but can be called from client-side forms. No need for separate API routes.
Viva Points to Remember
  • "What is React?" - A declarative, component-based JavaScript library for building user interfaces.
  • "What is the virtual DOM?" - A lightweight copy of the real DOM. React compares old vs new virtual DOM and only updates what changed. This is called reconciliation or diffing.
  • "What is the difference between state and props?" - Props are read-only data passed from parent to child. State is mutable data managed inside the component itself.
  • "What is useEffect?" - A hook that runs side effects after render, like API calls or subscriptions. It runs after every render by default, or only when specific dependencies change.

TypeScript 5 - Type Safety for JavaScript

Language
Beginner explanation: TypeScript is JavaScript with a superpower - you can tell the computer what TYPE of data each variable holds (string, number, object, etc.). It catches errors BEFORE your code runs. Think of it as spell-check for code.

Why We Use It

  • Catches bugs early: If you try to use a number as text, TypeScript stops you before the code even runs.
  • Better IDE experience: Autocomplete, inline documentation, and instant error highlighting in your editor.
  • Self-documenting: The types tell other developers exactly what data each function expects and returns.
  • Safer refactoring: When you change a data structure, TypeScript instantly shows you everywhere that needs updating.

Key Concepts

Basic Types

You declare what type each variable holds: string for text, number for digits, boolean for true/false, arrays for lists, and objects for structured data with specific properties.

Interfaces and Types

You define the shape of objects. For example, a "User" interface says every user must have a name (string) and email (string). This prevents you from accidentally creating a user without an email.

What is New in TypeScript 5?

  • satisfies operator: Validates that an object matches a type without changing what TypeScript infers about the object. You get validation AND precise type information.
  • const type parameters: Forces generics to infer specific literal values instead of broad types. No more writing "as const" everywhere.
  • ECMAScript Decorators: Official standard decorators that let you modify classes and methods cleanly. No more experimental compiler flags.
  • Multiple tsconfig extends: You can now extend multiple configuration files instead of just one, making monorepo setups cleaner.
  • Performance: 50-60 percent smaller package size and 10-25 percent faster compilation compared to older versions.
Viva Points to Remember
  • "Why TypeScript over JavaScript?" - Catches type errors at compile time, better IDE autocomplete, self-documenting code, safer refactoring.
  • "What is a generic?" - A type parameter that makes functions or components work with ANY type while still being type-safe. Like a placeholder that gets filled in when you use it.
  • "What is the difference between type and interface?" - Both define object shapes. Interfaces can be extended and merged. Types are more flexible for unions and intersections. In practice, they are interchangeable for most cases.

Tailwind CSS 3.4 - Utility-First Styling

Styling
Beginner explanation: Instead of writing separate CSS files, Tailwind lets you add styling directly in your HTML using short class names like "bg-blue-500 text-white p-4 rounded". It is like having a paint palette where each color and size is a class name you apply directly.

Why We Use It

  • Faster development: No context switching between HTML and CSS files. Everything is in one place.
  • Consistent design: Predefined spacing, colors, and sizes ensure your app looks uniform without manual CSS variables.
  • Small production CSS: Tailwind scans your code and only generates the CSS classes you actually use. Unused styles are purged.
  • Responsive by default: Classes like "md:flex" and "lg:text-xl" let you build responsive layouts without media queries in separate files.

What is New in Tailwind 3.4?

:has() Parent Selector

You can style a parent element based on what its children look like. For example, highlight a card when a checkbox inside it is checked. No JavaScript needed anymore.

size-* Utility

Set both width and height at once with a single class. Instead of writing "w-10 h-10", you just write "size-10".

  • CSS Subgrid: Nested grids can inherit column alignment from their parent grid, solving a long-standing layout problem.
  • Dynamic Viewport Units: "h-dscreen" resizes in real-time as mobile browser bars appear or disappear, fixing the mobile viewport height issue.
  • text-balance: Prevents ugly single orphan words at the end of long headings.
  • Children selector (*:): Style all children of an element from the parent class instead of adding classes to each child individually.
Viva Points to Remember
  • "Why Tailwind over CSS modules?" - Faster development, consistent design system, smaller production CSS through purging, responsive utilities built in.
  • "How does Tailwind purging work?" - It scans your source files for class names, generates only the CSS you use, and removes everything else. This keeps your final CSS file tiny.

Supabase + PostgreSQL 15 - The Database

Database
Beginner explanation: Supabase is a hosted backend that gives you a full PostgreSQL database, user authentication, real-time data subscriptions, and an auto-generated REST API - all from your database schema. Think of it as an open-source Firebase built on top of PostgreSQL.

Why We Use It

  • All-in-one backend: Database, authentication, file storage, and real-time subscriptions in a single platform. No need to stitch together five different services.
  • Auto-generated API: Every table you create automatically gets a REST API endpoint. No backend code needed for basic CRUD operations.
  • Row-Level Security: You write policies that control which rows each user can see or modify. Users can only access their own data.
  • Real-time subscriptions: Your frontend can listen for database changes in real-time. When someone inserts a row, connected clients see it instantly.
  • PostgreSQL extensions: Install PostGIS for geographic data and pgvector for AI embeddings with a single toggle.

PostgreSQL 15 Key Features

  • MERGE statement: Combine INSERT, UPDATE, and DELETE into one atomic operation. A cleaner way to do upserts.
  • Faster sorting: Internal sorting algorithms were optimized, making ORDER BY operations up to 4x faster on un-indexed data.
  • Stricter security: Default CREATE permissions on the public schema are revoked. Only the database owner can create tables.
  • Better replication: Filter specific rows and columns when replicating data to other databases for analytics.
Viva Points to Remember
  • "What is Supabase?" - Open-source Firebase alternative built on PostgreSQL. Provides database, auth, real-time subscriptions, edge functions, and auto-generated REST/GraphQL APIs.
  • "What is Row-Level Security?" - A PostgreSQL feature where you write policies to control which rows each user can read or write. Example: users can only see their own orders.
  • "Why PostgreSQL over MongoDB?" - PostgreSQL is relational (structured data with relationships), supports ACID transactions, has powerful extensions like PostGIS and pgvector, and is battle-tested for decades.

Prisma ORM - Database Client

Database
Beginner explanation: Prisma is a tool that lets you define your database tables in a special file called schema.prisma, then auto-generates a type-safe client to query those tables. No more writing raw SQL strings with typos!

Why We Use It

  • Type safety: Every database query is type-checked. If you try to access a column that does not exist, TypeScript catches it immediately.
  • Auto-generated client: After defining your schema, run "prisma generate" and you get a fully typed JavaScript/Python client with autocomplete.
  • Migration management: When you change your schema, "prisma migrate" generates the SQL needed to update your live database automatically.
  • Clean API: Query your database using method chains instead of raw SQL strings. More readable, less error-prone.

How It Works

  • Step 1: Define your models (tables) in schema.prisma with their fields, types, and relationships.
  • Step 2: Run "prisma generate" to create the type-safe client library.
  • Step 3: Run "prisma migrate" to apply schema changes to your database.
  • Step 4: Import the generated client in your code and use it for all database operations.
Viva Points to Remember
  • "What is an ORM?" - Object-Relational Mapper. It lets you interact with your database using your programming language objects and functions instead of writing raw SQL.
  • "Why Prisma over raw SQL?" - Type safety, auto-generated client, migration management, less boilerplate, IDE autocomplete for queries.
  • "What is a Prisma migration?" - A version-controlled SQL file that describes how to update your database schema. Prisma generates these automatically when you change your schema.

PostGIS - Spatial Database Extension

Database
Beginner explanation: PostGIS turns your regular Postgres database into a geographic database. You can store GPS coordinates as actual spatial data types, then run queries like "find all locations within 5km of this point" using pure SQL. It is blazingly fast thanks to spatial indexing.

Why We Use It

  • Proximity queries: Find all safety alerts, restaurants, or events near a user's GPS coordinates with a single SQL query.
  • Spatial indexing: Uses GiST (Generalized Search Tree) indexes that organize data geographically. Searching through millions of location rows takes milliseconds.
  • Server-side filtering: Instead of downloading all locations and filtering in JavaScript, the database does the heavy lifting and returns only what you need.
  • Precise calculations: Handles real-world distances on the curved surface of the Earth, not flat 2D math.

Geometry vs Geography

GEOMETRY (Flat Earth)

Uses X and Y coordinates on a flat 2D grid. Incredibly fast. Best for small local areas like a warehouse floor plan or city block.

GEOGRAPHY (Round Earth)

Uses true longitude and latitude on a 3D sphere. Mathematically precise over long distances. Handles real-world distances in meters natively.

Viva Points to Remember
  • "What is PostGIS?" - An open-source extension that adds geographic/spatial data types and functions to PostgreSQL.
  • "What is a spatial index?" - A special GiST index that organizes geographic data using bounding boxes, enabling instant proximity searches without scanning all rows.
  • "What is SRID 4326?" - The standard coordinate reference system for GPS (WGS 84). It defines how longitude/latitude numbers map to positions on Earth.

pgvector - AI Embedding Search

Database
Beginner explanation: AI models convert text into arrays of numbers called embeddings (e.g., 1536 numbers). Similar texts get similar number arrays. pgvector lets you store these arrays in Postgres and search for the most similar ones. This powers semantic search and RAG (Retrieval-Augmented Generation).

Why We Use It

  • Semantic search: Search by meaning, not keywords. A query about "safe walking routes" can find documents about "secure pedestrian paths" even though they share no common words.
  • RAG pipelines: Retrieve relevant documents from your database and inject them into an LLM prompt. This gives AI access to your private, up-to-date data.
  • No extra database: Store vectors alongside your regular data in the same Postgres database. Use standard SQL joins, transactions, and security policies.
  • Fast approximate search: HNSW indexes find the nearest vectors in milliseconds, even across millions of rows.

What is an Embedding?

An embedding is a long list of numbers (like 1532 floating-point values) that represents the meaning of a piece of text. The AI model reads the text and converts it into these numbers. Texts with similar meanings end up with similar number arrays. You can then measure "distance" between embeddings to find similar content.

Viva Points to Remember
  • "What is an embedding?" - A numerical vector (array of floats) that represents the semantic meaning of text or images. Similar meanings produce similar vectors.
  • "What is RAG?" - Retrieval-Augmented Generation. Instead of relying only on the LLM's training data, you retrieve relevant documents from a vector database and include them in the prompt.
  • "What is cosine similarity?" - A measurement of how similar two vectors are, regardless of their magnitude. Values close to 1 mean very similar; close to 0 means unrelated.

MapLibre GL + react-map-gl - Interactive Maps

Frontend
Beginner explanation: MapLibre GL is an open-source map renderer that draws vector maps using your device's GPU. react-map-gl wraps it into React components so you can use Map, Marker, Popup, and NavigationControl like regular React elements. It is completely free with no token fees.

Why We Use It

  • Fully open-source: No vendor lock-in, no API tokens, no usage fees. Community-maintained fork of Mapbox GL.
  • GPU-accelerated rendering: Map tiles render using WebGL and WebGPU. Smooth even with thousands of markers.
  • Declarative React integration: Add Source and Layer components to overlay data. React reactivity handles updating the map when your data changes.
  • Vector tiles: Map data is transmitted as binary vector data, not images. This allows interactive styling, rotation, 3D terrain, and smooth zooming.
  • Rich control set: Built-in navigation controls, geolocation, markers, popups, and layer management.

What is a Vector Tile?

Instead of pre-rendered image tiles (like Google Maps PNGs), vector tiles transmit the actual map data (roads, buildings, borders) as binary data. Your browser renders them in real-time using the GPU. This means you can change colors, zoom smoothly, rotate the map, and add custom overlays without reloading anything.

Viva Points to Remember
  • "Why MapLibre over Mapbox?" - MapLibre is fully open-source with no vendor lock-in or token fees. Mapbox GL JS became proprietary after version 1.
  • "What are vector tiles?" - Map data transmitted as binary vectors, allowing interactive styling, rotation, and 3D terrain rendering in the browser.
  • "How do you add custom data to the map?" - Use Source components to provide GeoJSON data and Layer components to define how it renders (fills, lines, circles, etc.).

Turf.js 7.4 - Client-Side Geospatial Analysis

Frontend
Beginner explanation: Turf.js does math with GPS coordinates right in the browser. It can calculate distances, create buffer zones around points, check if a point is inside a polygon, find intersections between areas, and more. It outputs standard GeoJSON that MapLibre can render directly.

Why We Use It

  • Instant feedback: No server round-trip needed for simple geo calculations. The user sees results immediately.
  • Works offline: All calculations happen in the browser, so they work without internet connectivity.
  • Standard output: Produces GeoJSON objects that plug directly into MapLibre map layers.
  • Rich function library: Distance calculations, area measurements, buffer creation, point-in-polygon checks, bounding boxes, intersections, and more.

Key Functions

turf.distance()

Calculate the distance between two GPS points in kilometers, miles, or meters.

turf.buffer()

Create a circle or polygon around a point. Used for delivery zones, safety perimeters, etc.

turf.booleanPointInPolygon()

Check if a GPS coordinate falls inside a polygon area. Used for geofencing.

turf.area()

Calculate the surface area of any GeoJSON shape in square meters.

turf.bbox()

Get the minimum bounding rectangle that contains a shape.

turf.intersect()

Find where two polygons overlap. Used for zone conflict detection.

How Turf Fits in the Stack

Raw GPS coordinates come from the API or device. Turf.js processes them in the browser (calculates buffers, checks containment, measures distances). The resulting GeoJSON shapes are passed directly to MapLibre for rendering on the map.

Viva Points to Remember
  • "What is GeoJSON?" - A standard JSON format for representing geographic features like points, lines, and polygons with their coordinates.
  • "Why Turf.js on the client?" - Reduces server load, gives instant feedback with no API round-trip, and works offline.
  • "How does Turf differ from PostGIS?" - Turf runs in the browser for simple client-side checks. PostGIS runs on the server for complex spatial queries on large datasets. Use both together.

Dexie.js 4 - IndexedDB Wrapper (Offline Database)

Frontend
Beginner explanation: IndexedDB is a built-in browser database that needs no server. Dexie makes it easy to use with a clean Promise-based API. It stores data locally so your app works offline. When internet comes back, a Service Worker syncs the data to the server.

Why We Use It

  • Offline-first data: User actions are saved locally in IndexedDB. The app works fully offline with instant read/write speeds.
  • Reactive queries: useLiveQuery hook automatically re-renders your React component whenever the underlying data changes.
  • Large storage: IndexedDB can store hundreds of megabytes of structured data, far more than localStorage.
  • Shared access: Both the main UI thread and background Service Worker can access the same database simultaneously.

How Offline Sync Works

  • Step 1: User performs an action (e.g., submits a form) while offline.
  • Step 2: The data is saved to IndexedDB via Dexie.
  • Step 3: Service Worker detects the failed network request and queues it.
  • Step 4: When connectivity returns, the Service Worker syncs queued data to the server.
  • Step 5: useLiveQuery updates the UI to show the sync status in real-time.
Important gotcha: Because Next.js runs code on the server first, you must always add "use client" at the top of any file that uses Dexie. IndexedDB only exists in the browser, not on the server.
Viva Points to Remember
  • "What is IndexedDB?" - A built-in browser database that stores structured data locally. Supports large datasets, indexes, and transactions.
  • "Why Dexie over raw IndexedDB?" - Dexie provides a clean Promise-based API, TypeScript type safety, and reactive queries with useLiveQuery.
  • "Why not just use localStorage?" - localStorage is limited to about 5MB, can only store strings, and is synchronous (blocks the UI). IndexedDB supports much more data, structured objects, and async operations.

PWA + Service Workers + Workbox

Frontend
Beginner explanation: A PWA (Progressive Web App) is a website that works like a native app. It can be installed on your phone, work offline, and send push notifications. The magic is the Service Worker, a background script that intercepts network requests and caches files for offline use.

Why We Use It

  • Offline functionality: The app works without internet by serving cached assets and queued data from IndexedDB.
  • Installable: Users can add the app to their home screen like a native app, without going through an app store.
  • Faster loading: Cached assets load instantly on repeat visits. No need to download the same files again.
  • Push notifications: The Service Worker enables receiving push notifications even when the app is closed.

What is Workbox?

Workbox is a Google library that makes Service Worker caching strategies easy. Instead of writing complex caching logic from scratch, you use predefined strategies like "cache everything on first visit" or "serve cached but also check for updates in background." next-pwa uses Workbox under the hood.

What is next-pwa?

next-pwa is a wrapper that simplifies adding PWA support to Next.js projects. It automatically generates the Service Worker, handles registration, and integrates with Workbox for caching strategies. You configure it in next.config and it does the heavy lifting.

Viva Points to Remember
  • "What is a Service Worker?" - A background JavaScript thread that intercepts HTTP requests. It can cache responses, serve cached content when offline, and handle push notifications.
  • "What is the app shell pattern?" - Cache the minimal UI (HTML, CSS, JS) so the app loads instantly, then fetch dynamic data when online.
  • "What is the difference between cache-first and network-first strategies?" - Cache-first serves cached content immediately (fast, may be stale). Network-first always tries the server first (fresh, slower). Use cache-first for static assets and network-first for dynamic data.

Web Push Notifications (VAPID)

Frontend + Backend
Beginner explanation: Web Push lets your server send notifications to a user's device even when your website is completely closed. VAPID keys are a security mechanism - a public/private keypair that proves YOUR server is the only one allowed to send notifications to your users.

Why We Use It

  • Re-engage users: Send safety alerts, location reminders, or AI analysis results directly to users even when they are not using the app.
  • No app store needed: Push notifications work through the browser. Users just need to grant permission.
  • Vendor-independent: Web Push is an open standard. No dependency on Firebase or Apple Push Notification Service directly.
  • Works with PWA: Combined with Service Workers, notifications can be displayed even when the app is not running.

What are VAPID Keys?

VAPID stands for Voluntary Application Server Identification. You generate a public key (shared in your frontend code) and a private key (kept secret on your server). When a user subscribes, the browser's push service verifies that only YOUR server can send notifications to that user. This prevents other servers from spamming your users.

Viva Points to Remember
  • "Can you send push notifications without user permission?" - No. The browser always asks the user to grant notification permission first.
  • "How does it work when the app is closed?" - The browser maintains a persistent connection to the push service (FCM for Chrome, Apple Push for Safari). When your server sends a push, the push service wakes up the browser, which triggers the Service Worker to display the notification.
  • "What is the role of the Push Service?" - It acts as a middleman between your server and the browser. Your server sends the notification to the Push Service (e.g., Google FCM), and the Push Service delivers it to the user's device.

FastAPI - Python Backend Framework

Backend
Beginner explanation: FastAPI is a Python framework for building APIs. It is extremely fast because it handles requests asynchronously, auto-generates interactive API documentation at /docs, and validates all incoming data automatically using Pydantic models.

Why We Use It

  • Speed: Built on ASGI (async server), it handles thousands of concurrent requests while waiting for database queries or other service calls.
  • Auto-generated docs: Every API endpoint automatically gets interactive documentation at /docs and /redoc. Frontend developers can test APIs without backend help.
  • Data validation: Pydantic automatically validates incoming JSON payloads. If a service sends malformed data, FastAPI rejects it with clear error messages.
  • Lightweight: Minimal overhead means containerized microservices start up rapidly and consume very little RAM.
  • Python ecosystem: Access to thousands of Python libraries for AI, data processing, and scientific computing.

Microservices Architecture

In our project, FastAPI powers the AI backend. The Next.js frontend sends requests to FastAPI endpoints, which orchestrate AI pipelines (LangChain/LangGraph), interact with the database, and return results. Each service can be independently scaled and deployed.

Viva Points to Remember
  • "Why FastAPI over Flask or Django?" - Native async/await support, automatic OpenAPI docs, Pydantic validation, 2-10x faster than Flask for async workloads.
  • "What is ASGI?" - Asynchronous Server Gateway Interface. The protocol that allows Python web frameworks to handle thousands of concurrent connections efficiently.
  • "What is Pydantic?" - A data validation library that automatically checks incoming JSON against your type definitions and returns clear error messages for invalid data.

LangChain - LLM Building Blocks

AI
Beginner explanation: LangChain provides building blocks for connecting LLMs (like GPT) to your data and tools. Think of it as LEGO bricks for AI - prompt templates, document loaders, vector store integrations, and tool wrappers that you snap together to build AI-powered features.

Why We Use It

  • Standardized interfaces: Switch between OpenAI, Anthropic, or local models with a single line of code. The rest of your pipeline stays the same.
  • RAG pipeline: Built-in tools for loading documents, splitting them into chunks, embedding them, storing in vector databases, and retrieving relevant chunks for LLM prompts.
  • LCEL (chain language): A clean pipe-operator syntax for chaining components together. Automatically handles streaming, async execution, and error handling.
  • Tool ecosystem: Give LLMs access to Google Search, databases, APIs, or any custom tool. The LLM decides which tool to use based on the user's question.

Core Concepts

Prompt Templates

Reusable prompt structures where you inject user input dynamically. Instead of hardcoding prompts, you define a template with placeholders and fill them at runtime.

RAG Pipeline

Load documents, split into chunks, embed with AI models, store in vector database, retrieve relevant chunks when user asks a question, and send them to the LLM as context.

Chains (LCEL)

Connect components using the pipe operator. Prompt goes in, LLM processes it, output parser cleans the result. Streaming and async are handled automatically.

Tools and Agents

Give LLMs access to external tools. An Agent uses the LLM as a reasoning engine to decide which tool to call and what arguments to pass based on user input.

Viva Points to Remember
  • "What is LangChain?" - An open-source framework that provides standardized building blocks for LLM applications - prompts, chains, retrieval, tools, and agents.
  • "What is RAG?" - Retrieval-Augmented Generation. Instead of relying only on the LLM's training data, you retrieve relevant documents and include them in the prompt.
  • "What is LCEL?" - LangChain Expression Language. A declarative way to chain components using the pipe operator. Automatically handles streaming, async, and error handling.

LangGraph - Stateful AI Agent Workflows

AI
Beginner explanation: While LangChain gives you building blocks, LangGraph gives you the blueprint. It lets you build AI workflows with loops, branches, and memory. If an AI agent fails a task, LangGraph can loop back, self-correct, and try again - like a human thinking through a problem.

Why We Use It

  • Self-correcting agents: If the AI retrieves irrelevant documents or generates a poor answer, LangGraph can loop back, try a different approach, and improve the result.
  • State management: A centralized state object acts as the app's memory, shared across all steps. Every node reads from and writes to this state.
  • Conditional routing: After each step, decide where to go next based on the result. If the answer is good, finish. If not, route to a correction node.
  • Multi-agent collaboration: Split complex tasks among specialized agents (researcher, writer, editor) that pass messages to each other within the same graph.
  • Built-in persistence: Automatically saves checkpoints after every node execution, giving agents perfect memory and the ability to rewind or replay steps.

Three Core Concepts

State

A shared data object that all steps read from and write to. Acts as the application's memory. Contains chat history, variables, retrieved documents, and task status.

Nodes

Python functions that perform actions. Each node receives the current state, executes logic (like calling an LLM or database), and returns an updated state.

Edges

Connections between nodes that define the flow of execution. Can be simple (A goes to B) or conditional (if error, loop back; if success, finish).

How LangChain and LangGraph Work Together

Think of it this way: LangChain = LEGO bricks. LangGraph = the structural blueprint telling you how to assemble them, when to loop, and when to branch. Each LangGraph node uses LangChain components inside. LangGraph manages the overall flow; LangChain manages the data processing within each step.

Viva Points to Remember
  • "LangChain vs LangGraph?" - LangChain provides linear chains and building blocks. LangGraph provides cyclical graphs with state management, loops, and multi-agent orchestration.
  • "When would you use LangGraph?" - When your AI workflow needs loops (retry on failure), conditional branching, multi-agent collaboration, or human-in-the-loop checkpoints.
  • "What is a State Graph?" - A directed graph where each node is a function and edges define control flow. State is passed through and mutated at each step.

WebLLM - Run AI Models in the Browser

AI
Beginner explanation: WebLLM uses WebGPU (your browser's GPU access) to run large language models completely on your device. No server needed! Zero API costs, total privacy, works offline. Models like Llama 3, Phi 3, and Gemma run right in Chrome.

Why We Use It

  • Zero server cost: The AI runs entirely on the user's device. No API calls to OpenAI or Anthropic needed for on-device tasks.
  • Complete privacy: Data never leaves the device. Perfect for processing sensitive location or personal data locally.
  • Works offline: Once the model is downloaded and cached, it works without internet connectivity.
  • OpenAI-compatible API: Uses the same API structure as OpenAI, so you can swap between local and cloud models easily.

How It Works

  • Step 1: The first time, the model weights are downloaded from a CDN (1-4GB depending on the model).
  • Step 2: The weights are cached in the browser's Cache Storage API.
  • Step 3: WebLLM compiles the quantized model weights into WebGPU compute shaders.
  • Step 4: Inference runs on the device's GPU. Subsequent loads are instant from cache.

Requirements

  • WebGPU support: Chrome 113+, Edge 113+, Opera 99+. Check navigator.gpu for availability.
  • GPU required: Needs a dedicated GPU for reasonable inference speeds.
  • Large first download: Models are 1-4GB. First load downloads; subsequent loads use browser cache.
Viva Points to Remember
  • "How can an LLM run in the browser?" - WebLLM uses WebGPU to access the device's GPU, compiles quantized model weights into GPU compute shaders, and runs inference locally.
  • "Why not just call the OpenAI API?" - WebLLM provides zero cost, full privacy, and offline capability. The trade-off is a large initial download and requiring a decent GPU.
  • "What is WebGPU?" - The successor to WebGL. Provides direct GPU compute access in the browser, enabling ML inference, 3D rendering, and parallel computing.

XGBoost - Gradient Boosted Decision Trees

ML
Beginner explanation: XGBoost is a machine learning algorithm that builds many small decision trees sequentially. Each new tree learns from the mistakes of the previous ones. It is incredibly fast and accurate for structured or tabular data like spreadsheets and databases. Famous for winning Kaggle competitions.

Why We Use It

  • Best-in-class accuracy: Consistently outperforms other algorithms on structured/tabular data. Dominates data science competitions.
  • Speed: Parallel processing for feature split-point search makes training extremely fast.
  • Handles messy data: Automatically deals with missing values, mixed data types, and outliers.
  • Built-in regularization: L1 and L2 penalties prevent overfitting, making the model generalize well to new data.

How It Works (Simple Analogy)

Imagine a group of students taking a test. The first student makes a baseline attempt. The teacher identifies which questions they got wrong. The next student focuses only on those wrong answers. The third student focuses on what the second student still got wrong. This continues until the group collectively gets an excellent score. Each student is a "tree," and they learn from previous mistakes.

Why "Extreme"?

  • Built-in regularization: L1 (Lasso) and L2 (Ridge) penalties to prevent overfitting.
  • Parallel processing: Split-point search across features is parallelized.
  • Missing data handling: Automatically learns the best branch for missing values.
  • Tree pruning: Removes splits that do not improve the model beyond a threshold.
Viva Points to Remember
  • "XGBoost vs Random Forest?" - Random Forest builds trees independently (parallel). XGBoost builds sequentially (each tree learns from previous errors). XGBoost is usually more accurate but needs careful tuning.
  • "What is gradient boosting?" - An ensemble method where each new model corrects the errors of the combined previous models. The "gradient" refers to using gradient descent to minimize the loss function.
  • "What are key hyperparameters?" - learning_rate (step size), max_depth (tree complexity), n_estimators (number of trees), min_child_weight (minimum samples per leaf).

Playwright - End-to-End Testing

Testing
Beginner explanation: Playwright is a testing tool by Microsoft that launches real browsers (Chrome, Firefox, Safari) and automates user actions like clicking buttons, filling forms, and navigating pages. It is like having a robot that tests your app the way a real user would.

Why We Use It

  • True cross-browser testing: Test on Chromium, Firefox, and Safari (WebKit) using the exact same test code. No separate tools for each browser.
  • Auto-waiting: Automatically waits for elements to be visible, stable, and clickable before performing actions. No more flaky tests from hardcoded sleep commands.
  • Parallel execution: Launch multiple isolated browser contexts (like incognito windows) to run tests concurrently. Dramatically cuts test execution time.
  • Built-in API testing: You can test backend API endpoints directly without needing a separate HTTP client library.
  • Excellent debugging: Playwright Inspector, Trace Viewer (records videos, screenshots, and network logs), and Codegen tool that generates test code as you click around.

Ultimate Viva Q&A - Top Questions and Answers

Viva Prep
Q1: Give a 2-minute overview of your project.
A: SafeSphere is a location-aware, AI-powered Progressive Web App built with Next.js 14 and React 18 on the frontend, Supabase with PostgreSQL 15 using PostGIS for spatial queries and pgvector for AI semantic search on the database, FastAPI with LangChain and LangGraph for AI orchestration on the backend, MapLibre GL and Turf.js for interactive maps, Dexie and Service Workers for offline-first PWA capabilities, Web Push with VAPID for notifications, WebLLM for in-browser AI inference, and Capacitor 8.5 to deploy as native iOS and Android apps.
Q2: What is the difference between SSR, SSG, and ISR?
A: SSR (Server-Side Rendering) renders the page on every request, so data is always fresh but slower. SSG (Static Site Generation) builds the page once at build time, making it the fastest but data gets stale. ISR (Incremental Static Regeneration) creates a static page that re-generates in the background after a set time interval, giving you the best of both worlds.
Q3: How does offline-first work in your project?
A: Dexie.js stores user actions in IndexedDB locally. The Service Worker (configured via next-pwa and Workbox) intercepts failed network requests and queues them. When the user comes back online, the queued data syncs to the server. The useLiveQuery hook provides reactive UI that updates in real-time as local data changes.
Q4: What is RAG and how do you implement it?
A: RAG stands for Retrieval-Augmented Generation. Instead of relying only on the LLM's training data, we use LangChain to load documents, split them into chunks, embed them with AI models, and store them in pgvector. When a user asks a question, we convert it to a vector, find the most similar document chunks using cosine similarity, and inject them into the LLM prompt. This gives the LLM access to our private, up-to-date data without fine-tuning.
Q5: How do LangChain and LangGraph work together?
A: LangChain provides the building blocks - prompt templates, LLM wrappers, document loaders, tools. LangGraph provides the structural architecture - state management, conditional routing, loops, and multi-agent coordination. In our project, each LangGraph node uses LangChain components inside. For example, a "grade documents" node uses a LangChain chain to evaluate relevance, and LangGraph decides whether to loop back or proceed.
Q6: What is PostGIS and why do you use it?
A: PostGIS is a PostgreSQL extension that adds geographic and spatial data types. We use it to store GPS coordinates as GEOGRAPHY columns and run proximity queries like "find all safety alerts within 5km of the user." The GiST spatial index makes these queries instant even with millions of rows. On the frontend, Turf.js handles simpler client-side geo calculations.
Q7: What is the role of WebLLM in your project?
A: WebLLM runs LLM inference entirely in the browser using WebGPU. This means zero server costs, complete user privacy because data never leaves the device, and offline capability. We use it for on-device tasks like summarizing location reports or classifying safety zones - tasks that do not need a massive cloud model.
Q8: How does Capacitor differ from React Native?
A: Capacitor wraps your existing web code in a native WebView - you write once in React and deploy to iOS, Android, and Desktop. React Native uses native UI components and bridges to them via JavaScript. Capacitor is faster to develop because you reuse web code, while React Native has better native feel and performance for complex animations.
Q9: How do you handle authentication and security?
A: We use Supabase Auth for user authentication with email, password, and OAuth options. Database security is enforced via Row-Level Security policies - users can only access their own data. VAPID keys authenticate our push notification server. FastAPI with Pydantic validates all incoming API payloads.
Q10: What testing strategy do you use?
A: We use Playwright for end-to-end testing. It launches real browsers (Chromium, Firefox, WebKit) and simulates user workflows. It has built-in auto-waiting, isolated browser contexts for parallel execution, and generates test reports with screenshots and videos. We also use TypeScript as a form of static testing, catching bugs at compile time before code even runs.
